## 一、项目概述

### 1.1 商业化目标

将现有的单用户 Rust+ Dashboard 改造为**多租户 SaaS 平台**，核心特点：

- ✅ 用户注册/登录系统
- ✅ 订阅付费（支付宝/微信支付）
- ✅ 多用户数据隔离
- ✅ **功能完全一致，仅服务时间区别**
- ✅ 单体应用架构（保持现有优势）

### 1.2 核心原则

**功能无差异化**：
- 所有用户功能完全相同
- 不限制服务器数量
- 不限制功能模块
- 唯一区别：订阅有效期

**架构简化**：
- 采用单体应用而非微服务
- 降低复杂度和运维成本
- 保持现有 EventEmitter 驱动架构优势

### 1.3 当前架构问题

**单用户设计**：
- 所有数据全局共享，无用户概念
- FCM 凭证单例（只支持一个用户）
- 服务器连接池全局共享
- 无认证和权限控制

**需要解决**：
- 多租户数据隔离
- 每个用户独立的 FCM 连接
- 每个用户独立的 RustPlus 连接池
- 用户认证和会话管理
- 订阅时间控制

### 2.2 服务层设计

**GlobalServiceManager（全局管理器）**：
- 管理所有用户的 UserServiceManager 实例
- 启动时初始化所有有效订阅用户
- 定时检查订阅到期（每小时）
- 监听支付事件（创建/恢复用户服务）

**UserServiceManager（用户服务管理器）**：
- 每个用户一个独立实例
- 包含该用户的所有服务（RustPlus、FCM、事件监控等）
- 订阅到期时自动销毁
- 续费后自动恢复

### 2.3 与当前架构的对应关系

| 当前架构 | 重构后架构 |
|---------|-----------|
| `RustPlusService`（全局单例） | `GlobalServiceManager` + 多个 `UserServiceManager` |
| `FCMService`（全局单例） | 每个 `UserServiceManager` 内的 `FCMManager` |
| `EventMonitorService`（全局单例） | 每个 `UserServiceManager` 内的 `EventMonitor` |
| `AutomationService`（全局单例） | 每个 `UserServiceManager` 内的 `Automation` |
| `CommandsService`（全局单例） | 每个 `UserServiceManager` 内的 `Commands` |

## 三、订阅模型

### 3.1 时间订阅制

**核心原则**：功能完全一致，仅服务时间不同

| 套餐 | 定价 | 服务时长 | 说明 |
|------|------|----------|------|
| **试用版** | ¥0 | 7 天 | 注册即送，到期自动停止 |
| **月付** | ¥29 | 30 天 | 完整功能 |
| **季付** | ¥79 | 90 天 | 优惠 8%（相当于 ¥26.3/月） |
| **年付** | ¥299 | 365 天 | 优惠 15%（相当于 ¥24.9/月） |

**特点**：
- 无服务器数量限制
- 无功能限制
- 所有用户平等

### 3.2 用户生命周期

**注册时**：
```
用户注册
  ↓
自动开启 7 天试用
subscription_expires_at = now() + 7天
  ↓
创建 UserServiceManager 实例
启动所有服务
```

**付费后**：
```
用户完成支付
  ↓
延长订阅时间
subscription_expires_at += duration_days
  ↓
如果实例不存在 → 创建
如果已存在 → 继续使用
```

**到期时**：
```
定时任务检测（每小时）
  ↓
subscription_expires_at < now()
  ↓
断开所有连接
停止所有服务
删除 UserServiceManager 实例
保留数据 30 天
```

**续费后**：
```
用户续费
  ↓
延长订阅时间
  ↓
重新创建 UserServiceManager 实例
恢复所有服务
```

### 3.3 宽限期设计（推荐）

```
到期当天：
  服务正常运行
  前端显示红色横幅："订阅已到期，3 天后将停止服务"

到期第 1-3 天：
  服务继续运行（宽限期）
  每天发送邮件提醒
  前端倒计时显示

到期第 4 天：
  停止所有服务
  前端跳转到支付页面

到期第 34 天：
  删除用户数据（提前 7 天邮件通知）
```

## 四、数据库设计

### 4.1 MySQL Schema

```sql
-- ==================== 用户表 ====================
CREATE TABLE users (
  id VARCHAR(36) PRIMARY KEY COMMENT 'UUID',
  email VARCHAR(255) NOT NULL UNIQUE,
  password_hash VARCHAR(255) NOT NULL COMMENT 'bcrypt',

  -- 订阅相关（简化）
  subscription_expires_at BIGINT COMMENT '订阅到期时间（Unix 毫秒）',
  is_trial BOOLEAN DEFAULT TRUE COMMENT '是否试用账号',
  trial_started_at BIGINT COMMENT '试用开始时间',

  status ENUM('active', 'suspended', 'deleted') DEFAULT 'active',
  email_verified BOOLEAN DEFAULT FALSE,

  created_at BIGINT NOT NULL,
  updated_at BIGINT NOT NULL,
  last_login_at BIGINT,

  INDEX idx_email (email),
  INDEX idx_subscription (subscription_expires_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

-- ==================== 订阅订单表 ====================
CREATE TABLE subscriptions (
  id VARCHAR(36) PRIMARY KEY,
  user_id VARCHAR(36) NOT NULL,

  plan ENUM('trial', 'monthly', 'quarterly', 'yearly') NOT NULL,
  amount DECIMAL(10, 2) NOT NULL,
  duration_days INT NOT NULL COMMENT '服务天数',

  payment_provider ENUM('alipay', 'wechat') NOT NULL,
  payment_id VARCHAR(255),
  status ENUM('pending', 'active', 'expired', 'cancelled') DEFAULT 'pending',

  started_at BIGINT,
  expires_at BIGINT,
  created_at BIGINT NOT NULL,
  updated_at BIGINT NOT NULL,

  FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE,
  INDEX idx_user (user_id),
  INDEX idx_status (status)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

-- ==================== 服务器表 ====================
CREATE TABLE servers (
  id VARCHAR(36) PRIMARY KEY,
  user_id VARCHAR(36) NOT NULL,

  name VARCHAR(100) NOT NULL,
  ip VARCHAR(45) NOT NULL,
  port VARCHAR(10) NOT NULL,
  player_id VARCHAR(20) NOT NULL COMMENT 'Steam ID',
  player_token VARCHAR(20) NOT NULL COMMENT '配对令牌',

  battlemetrics_id VARCHAR(20),
  img TEXT,
  logo TEXT,
  url VARCHAR(255),
  description TEXT,

  created_at BIGINT NOT NULL,
  updated_at BIGINT NOT NULL,

  FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE,
  INDEX idx_user (user_id),
  UNIQUE KEY uk_user_server (user_id, ip, port)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

-- ==================== 设备表 ====================
CREATE TABLE devices (
  id INT AUTO_INCREMENT PRIMARY KEY,
  user_id VARCHAR(36) NOT NULL,
  server_id VARCHAR(36) NOT NULL,

  entity_id INT NOT NULL,
  name VARCHAR(100) NOT NULL,
  type ENUM('switch', 'alarm', 'storage_monitor'),

  command VARCHAR(50),
  auto_mode TINYINT DEFAULT 0 COMMENT '0-8',

  reachable BOOLEAN DEFAULT TRUE,
  last_trigger BIGINT,

  created_at BIGINT NOT NULL,
  updated_at BIGINT NOT NULL,

  FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE,
  FOREIGN KEY (server_id) REFERENCES servers(id) ON DELETE CASCADE,
  INDEX idx_user (user_id),
  UNIQUE KEY uk_server_entity (server_id, entity_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

-- ==================== FCM 凭证表 ====================
CREATE TABLE fcm_credentials (
  id INT AUTO_INCREMENT PRIMARY KEY,
  user_id VARCHAR(36) NOT NULL UNIQUE,

  credentials_json TEXT NOT NULL,
  credential_type ENUM('GCM', 'FCM') NOT NULL,

  created_at BIGINT NOT NULL,
  updated_at BIGINT NOT NULL,

  FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

-- ==================== 事件日志表 ====================
CREATE TABLE event_logs (
  id BIGINT AUTO_INCREMENT PRIMARY KEY,
  user_id VARCHAR(36) NOT NULL,
  server_id VARCHAR(36) NOT NULL,

  event_type VARCHAR(50) NOT NULL,
  event_data JSON,

  created_at BIGINT NOT NULL,

  FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE,
  FOREIGN KEY (server_id) REFERENCES servers(id) ON DELETE CASCADE,
  INDEX idx_user_server (user_id, server_id),
  INDEX idx_created_at (created_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

-- ==================== 通知设置表 ====================
CREATE TABLE notification_settings (
  id INT AUTO_INCREMENT PRIMARY KEY,
  user_id VARCHAR(36) NOT NULL UNIQUE,

  settings_json JSON NOT NULL,

  created_at BIGINT NOT NULL,
  updated_at BIGINT NOT NULL,

  FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

### 4.2 核心字段说明

**users.subscription_expires_at**：
- `NULL` 或 `< now()`：服务已停止
- `>= now()`：服务正常运行
- 核心判断字段

**users.is_trial**：
- 区分试用和付费用户（统计用）
- 不影响功能

**subscriptions.duration_days**：
- trial: 7 天
- monthly: 30 天
- quarterly: 90 天
- yearly: 365 天

## 五、服务启动和停止策略

### 5.1 应用启动时

```
应用启动
  ↓
GlobalServiceManager.initializeAllActiveUsers()
  ↓
查询数据库：
  SELECT * FROM users
  WHERE subscription_expires_at >= ?
  AND status = 'active'
  ↓
为每个用户创建 UserServiceManager 实例
  ├─ 加载 FCM 凭证
  ├─ 启动 FCM 监听器（常驻）
  ├─ 加载服务器列表
  └─ 不自动连接（节省资源）
  ↓
启动定时任务（检查订阅到期）
```

### 5.2 用户登录后

```
用户登录（前端 WebSocket 连接）
  ↓
验证 JWT
socket.userId = decoded.userId
  ↓
检查订阅是否有效
  if (user.subscription_expires_at < now()) {
    返回错误："订阅已到期"
  }
  ↓
获取或创建 UserServiceManager 实例
  userService = GlobalServiceManager.getUserService(userId)
  ↓
加入用户专属房间
  socket.join(`user:${userId}`)
  ↓
用户点击"连接服务器"
  ↓
userService.connectToServer(serverId)
  ├─ 创建 RustPlus 连接
  ├─ 启动 EventMonitor
  └─ 启动 Automation
```

### 5.3 用户登出后

```
用户关闭浏览器/断开 WebSocket
  ↓
关闭 WebSocket 连接
  ↓
但保持 UserServiceManager 实例运行
  ├─ FCM 监听器继续运行（接收推送）
  ├─ RustPlus 连接继续运行（监控事件）
  └─ 事件通过 WebSocket 推送（用户下次登录时看到）
```

### 5.4 订阅到期处理

```
定时任务（每小时执行）
  ↓
查询到期用户：
  SELECT id FROM users
  WHERE subscription_expires_at + 3天 < now()
  ↓
对每个用户：
  1. 获取 UserServiceManager 实例
  2. 调用 userService.shutdown()
     ├─ 断开所有 RustPlus 连接
     ├─ 停止 FCM 监听器
     ├─ 停止事件监控
     └─ 停止自动化
  3. 从 Map 中删除实例
  4. 保留数据库数据
  5. 发送邮件："您的订阅已到期"
```

### 5.5 支付成功处理

```
支付宝/微信回调
  ↓
验证签名
  ↓
更新数据库：
  UPDATE users
  SET subscription_expires_at = subscription_expires_at + duration_days
  WHERE id = ?
  ↓
检查 UserServiceManager 是否存在
  ├─ 存在 → 无需操作（继续使用）
  └─ 不存在 → 创建新实例
  ↓
WebSocket 通知前端："订阅已续费"
```

## 七、代理配置

### 7.1 全局环境变量配置

**保持原方案**，通过环境变量全局配置代理：

```yaml
# docker-compose.yml
services:
  proxy:
    image: v2fly/v2fly-core:latest
    volumes:
      - ./proxy/config.json:/etc/v2ray/config.json
    ports:
      - "10808:10808"

  backend:
    environment:
      - HTTP_PROXY=http://proxy:10809
      - HTTPS_PROXY=http://proxy:10809
      - ALL_PROXY=socks5://proxy:10808
      - NO_PROXY=mysql,redis
```

**应用内使用**：
```javascript
// 启动时读取环境变量
const proxyAgent = process.env.ALL_PROXY
  ? new SocksProxyAgent(process.env.ALL_PROXY)
  : null;

// RustPlus 自动使用
const rustplus = new RustPlus(ip, port, playerId, playerToken, {
  agent: proxyAgent
});
```
