# 重构指南

> 本文档用于指导 Claude Code 进行重构工作
>
> **重要**：每次重构前，请先阅读本文档

---

## 一、重构目标

### 1.1 核心目标

将单用户 Rust+ Dashboard 改造为**多租户 SaaS 平台**，实现：

1. **用户系统**：注册、登录、JWT 认证
2. **多租户隔离**：每个用户独立的服务实例
3. **订阅管理**：时间订阅制，功能完全一致
4. **支付集成**：支付宝 + 微信支付
5. **数据迁移**：SQLite → MySQL

### 1.2 非目标

❌ 不采用微服务架构（保持单体）
❌ 不做功能差异化（所有用户功能一致）
❌ 不关注成本和时间优化（按实际需求开发）
❌ 不实现代理池（保持全局环境变量配置）

---

## 二、重构原则

### 2.1 架构原则

**保持单体**：
- 所有功能在一个应用内
- 不拆分微服务
- 保持现有 EventEmitter 驱动架构

**用户隔离**：
- 每个用户独立的 UserServiceManager 实例
- 独立的连接池、FCM 监听器、事件监控
- 数据库所有表添加 user_id 字段

**功能平等**：
- 所有用户功能完全一致
- 无服务器数量限制
- 无功能模块限制
- 唯一区别：订阅有效期

### 2.2 开发原则

**渐进式改造**：
- 先实现核心功能（认证、用户隔离）
- 再实现支付集成
- 最后实现前端改造

**向后兼容**：
- 保留现有数据结构
- 提供数据迁移脚本
- 可回滚到旧版本

**测试优先**：
- 每个阶段完成后进行测试
- 确保功能正常后再进行下一阶段

## 五、重构注意事项

### 5.1 数据库相关

**Schema 设计**：
- 使用 Prisma Schema 定义
- 所有表必须包含 user_id 字段
- 外键级联删除（ON DELETE CASCADE）
- 时间戳使用 BigInt（Unix 毫秒）

**数据迁移**：
- 先备份 SQLite 数据
- 使用 Prisma Migrate 生成迁移脚本
- 验证数据完整性
- 保留 SQLite 文件 30 天作为备份

**查询优化**：
- 所有查询必须带 WHERE user_id = ?
- 创建必要的索引
- 避免 N+1 查询

### 5.2 服务层相关

**UserServiceManager**：
- 每个用户一个实例
- 包含所有子服务（RustPlus、FCM、EventMonitor 等）
- 订阅到期时自动销毁
- 续费后自动恢复

**GlobalServiceManager**：
- 管理所有用户实例
- 定时检查订阅到期（每小时）
- 应用启动时初始化所有有效用户

**WebSocket**：
- 连接时验证 JWT
- 加入用户专属房间（`user:${userId}`）
- 广播时指定房间

### 5.3 前端相关

**路由保护**：
- 私有路由需要 JWT
- 订阅到期跳转到支付页面
- 未登录跳转到登录页面

**状态管理**：
- 订阅信息存储在全局状态
- 实时更新剩余天数
- WebSocket 断线自动重连

**支付流程**：
- 轮询订单状态（每 2 秒）
- 最多轮询 5 分钟
- 超时提示手动刷新

## 六、常见问题

### Q1: 如何处理现有数据？

**A**: 使用数据迁移脚本：
1. 所有现有数据归属到一个默认用户
2. 为默认用户设置永久订阅
3. 其他新用户正常注册使用

### Q2: 订阅到期后数据怎么办？

**A**: 宽限期策略：
- 到期后 3 天：服务继续运行（宽限期）
- 第 4 天：停止服务，保留数据
- 第 34 天：删除数据（提前 7 天通知）

### Q3: 如何测试支付功能？

**A**: 使用沙箱环境：
- 支付宝：使用沙箱账号
- 微信：使用测试号
- 内网穿透（ngrok）接收回调

### Q4: 多个用户同时连接同一个服务器会冲突吗？

**A**: 不会冲突：
- 每个用户的 RustPlus 连接是独立的
- 使用不同的 Steam ID 和 Token
- 数据库通过 user_id 隔离

### Q5: 如何回滚到旧版本？

**A**: 回滚步骤：
1. 停止新版本应用
2. 还原 SQLite 数据库备份
3. 启动旧版本应用
4. 验证功能正常

## 七、开发规范

### 7.1 命名规范

**文件命名**：
- 服务类：`*.service.js`
- 路由：`*.routes.js`
- 中间件：`*.middleware.js`
- 模型：Prisma Schema

**变量命名**：
- userId（用户 ID）
- serverId（服务器 ID）
- subscriptionExpiresAt（订阅到期时间）

### 7.2 注释规范

**关键逻辑必须注释**：
```javascript
/**
 * 创建用户服务实例
 * @param {string} userId - 用户 ID
 * @returns {Promise<UserServiceManager>}
 */
async createUserService(userId) {
  // 检查实例是否已存在
  if (this.userServices.has(userId)) {
    return this.userServices.get(userId);
  }

  // 创建新实例
  const userService = new UserServiceManager(userId);
  await userService.initialize();

  return userService;
}
```

### 7.3 错误处理

**统一错误格式**：
```javascript
throw new Error('订阅已到期');  // 业务错误
console.error('数据库连接失败:', error);  // 系统错误
```

**前端错误显示**：
- 使用 toast 提示
- 记录错误日志
- 关键错误上报
